## 分析服务恢复与多天统计（2026-11-16）

- 分析服务连接失败与 APM / XRAY / Vesta 授权失败分别展示；连接暂时失败自动重试一次，证书错误、读取超时和 HTTP 402 不自动重放。
- 支持检测分析服务、在输入框为空时重试原问题。额度耗尽会明确引导恢复项目额度，不提示重登数据平台。网络检查不代表模型额度可用。
- JS 错误多天计数使用 `apm.metric_range`，最多七天，按不超过24小时的窗口查询，由程序相加。失败、空分组及达到分组上限分别记录，不据部分结果给出全量占比，不相加比率或分位数。
- `jsErrorCount` 定义接口未命中时，只使用官方 CLI 随包文档中已确认的内置计数与维度参考，明确标注来源并保留原查询失败；不伪造接口定义返回。
- 当前官方 CLI 的数组参数采用重复选项，例如 `--group-by context_platform --group-by measurement_data.errorType`；不能把逗号连接的字符串当作已正确传入多个维度。
- 七天官方 CLI 实测结果和逐段审计见 `artifacts/circles-js-error-week-20261116.json`。这是固定时刻的验证快照，不冒充之后的新查询。

## 边界

- 自动时间定位：已知样本时间仅用于提示新查询；未知 Trace 按 24 小时窗口检索最近 7 天，命中停止。
- 标识：同 Trace、同会话、同用户和仅时间相近分别表达；没有 Request ID 时不宣称请求级精确证明。
- 5,000 ms 是错误文案阈值；duration=0 不作为实测耗时。网关原始秒值转换为毫秒，不用跨端差值归因网络。
- 预置 APM / XRAY 与 Vesta 各自保留采集时间。在线结果单独标记，不用快照冒充当前查询。
- 日志未回传、未命中、权限错误、平台超时分开保留。

## 工程

`app.py`：FastAPI、SSO、身份核对、异步查询与案件接口。

`trace_agent.py`：Runway 分析、受控工具调用、服务故障分类、分段指标汇总与调查历史。

`case_store.py`：PostgreSQL 共享案件保存与恢复；使用平台自动注入的 db.properties，不打包连接凭据。

`scripts/collect_evidence.py`：官方 APM / XRAY 采集和脱敏。

`scripts/vesta_evidence.py`：官方 Vesta CLI 调用、既有任务复用、状态核对、下载与片段关联。只通过官方 CLI；下载文件在临时目录处理，原始日志不写入公共示例。

`assets/`：调查工作台、关联规则、真实脱敏快照与报告。

`runtime/`：官方 APM CLI 及 Linux XRAY / Vesta 二进制，不含授权缓存。
